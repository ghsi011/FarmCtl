# Pico integration: working slices to release-ready PR

## Goal and boundaries

Deliver the agreed Android diagnostics, private fleet configuration, signed automatic Pico updates, and recoverable two-slot monitoring in a reviewed PR. Preserve deployed temperature Gists and history. Do not change either deployed board, merge, tag, or publish a production release under this plan. The non-critical spare and disposable GitHub resources are authorized for tests; test credentials must enter locally and never appear in source, issues, logs, or releases.

This plan extends the decisions in [the wayfinding map](https://github.com/ghsi011/FarmCtl/issues/31), especially the [handoff](https://github.com/ghsi011/FarmCtl/issues/39), without treating the unpassed [rollout gate](https://github.com/ghsi011/FarmCtl/issues/43) as an implementation blocker. Its passing evidence is required before a production cutover or automatic releases on deployed devices. The existing `.agent/ExecPlan.md` concerns the earlier app milestone; do not rewrite that history.

## Iterations (each leaves a runnable check)

1. **Visible read-only app slice — [#44](https://github.com/ghsi011/FarmCtl/issues/44).** Keep the existing temperature parser, samples, and alarms. Associate an optional diagnostics Gist and immutable device reference, fetch a bounded versioned snapshot, and render its age and reported health independently on the thermostat detail page. Validate legacy, stale, malformed, mismatched, and failed-fetch cases with synthetic fixtures and migration/widget tests. No new alarms or background scheduler yet.
2. **Spare-to-phone telemetry — [#45](https://github.com/ghsi011/FarmCtl/issues/45).** Build the smallest sanitized Pico monitor that publishes fresh temperature samples with changing markers to a disposable temperature Gist and redacted heartbeat to a separate diagnostics Gist. Host-test failed samples and outages, then verify on the identified spare with locally entered test credentials. Automatic updater and remote configuration remain disabled in this slice.
3. **Configuration and incident path.** Implement the private 65,536-byte fleet contract and safe phone compare-and-swap editor. Device applies candidate configuration with retained-good fallback and exact acknowledgements. Extend diagnostics events/retention and phone alarms without changing existing temperature freshness. Test local and spare behavior before expanding scope.
4. **Signed code delivery and recovery.** Add independent Pico release workflow/manifests/signature verification, staged two-slot supervisor, trial/rollback, and release discovery. Keep Android `v*` tags independent. Qualify combined runtime, storage, watchdog, failures, and power-cut recovery on the spare; leave unpassed scenarios explicitly blocked in #43. No firmware is published as stable before evidence passes.
5. **Release-ready review.** Run codegen, format, analyze, full parsing/app tests with coverage, relevant Pico tests, independent security/correctness review plus validator, and GitHub PR CI. Audit artifacts for secrets. Open a concise PR; wait for owner approval before merge or tag. Deployment needs a separate explicit authorization and the #43 gate.

## Work rules and progress

- Build one testable slice at a time; do not wait for the whole updater to make the app view useful.
- Preserve the existing uncommitted `/wifi.txt` ignore protection in the original checkout. This isolated branch starts from `origin/master`; do not read or copy secrets from the original Pico checkout.
- GitHub is the only backend. Ordinary NTP is an accepted but unauthenticated cold-boot bootstrap; preserve TLS CA/hostname verification and independent Ed25519 verification. No clock or network means no trusted network update, not a fabricated recovery success.
- Separate host-test PASS, spare-test PASS, CI PASS, and production rollout qualification. Record exact build, fixture, and limitations for each.
- First validate a real full-size fleet file by downloading to bounded staging, closing TLS, then parsing and validating from storage. The failed full-buffer parse and timed-out block-backed retry are not passes. Limit each schema field and collection without reducing the accepted 65,536-byte file envelope; include duplicate and malformed-tail cases.
- Host-model two consecutive A/B updates and every metadata interruption before spare power cuts. Never assume a directory rename and metadata write form one transaction. An unknown configuration compatibility with both running and retained-good code disables remote editing.
- Prove fixture-signed offline recovery before adding paginated release discovery. Restrict the signing key to a protected job; PR jobs never receive it. Ordinary NTP does not establish trustworthy certificate time or confidentiality against a capable active attacker.
- Spare-to-Gist testing needs a disposable user-scoped classic `gist` token: GitHub does not document Gist write support for repo-scoped fine-grained PATs or Actions installation tokens. Use a dedicated test account and short-lived `gist`-only classic token; the existing broad `gh` OAuth login may create synthetic test resources from the host but must not be copied to the Pico. Private Contents tests need a separate repo-limited Contents credential. Human token/account provisioning is an external prerequisite; do not downgrade auth to bypass it.
